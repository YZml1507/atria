## 1. 项目定位

- **交付物**：离线渲染视频 + 说明.md + GitHub 仓库
- **核心主张**：每个居民拥有永不丢失的个人全量记忆（512K 上下文窗口）：**全量时间线让 agent 能分辨传言在传播中的变异**（v1.1 按实测数据更新，详见 6.4）
- **差异化**：不复现 Smallville，融合三个项目：
  - Smallville（地图层级 + 作息锚点 + react 联想记忆的反面教材）
  - AI Town（单句 plan 的极简主义）
  - AgentSociety（分布生成器 + 显式关系图）
- **硬约束**：4 核 / 3.6G 内存 / 无 GPU；RPM≈50（实测 52.5）；manim + ffmpeg + edge-tts

## 2. 情景 A：包裹错领（14 天信息追踪弧线）

### 2.1 种子结构 `[实测，对照 Smallville 25 份 scratch.json]`

| 角色 | Smallville 原型 | 情景 A 定义 | 人数 |
|---|---|---|---|
| 意图持有者 | Isabella（currently 写派对，逢人就说） | 失主 Agent A：包裹被错领，要查清真相 | 1 |
| 态度种子 | Sam Moore（宣布参选） | 错领者：知道自己拿了别人的东西 | 1 |
| 碎片目击者 | —（Smallville 无此角色，我们的创新） | 各只看到碎片（方向/时间/部分特征，互相矛盾） | 3 |
| 好奇心放大器 | John/Yuriko/Giorgio/Adam/Latoya（5 人写 "curious about mayor"） | 高连接度人格，传言经他们扩散 | 5 |
| 中性背景板 | 18 人纯职业日常 | 纯职业日常 | 15 |

**设计原则（来自 Smallville 实证）**：钩子只写「信息从哪来、到谁手里」，**绝不写后果**。Smallville 的 8 个钩子全部写在 `currently` 字段、平均 43–53 词，论文的情人节派对结局没有一行是写出来的。

### 2.2 弧线节奏（只控制种子投放时间）

- 第 1–2 天：潜伏期，日常建立关系基线
- 第 2 天夜：引爆点（包裹错领，3 目击者各存碎片）
- 第 3–10 天：传播期（A 逢人打听；碎片经 5 放大器传播，每次复述经 LLM 记忆摘要 → 传言变异）
- 第 12–14 天：抉择期（A 决定当面对质谁）

**不写结局**：传言会不会先传到错领者本人？3 个碎片版本会不会互相冲突导致镇上分裂？A 会不会质错人？全部是运行结果。

### 2.3 为什么情景 A 是 512K 主张的唯一载体 `[实测]`

A 最终的决策只取决于他个人 12 天里陆续听到的全部内容：

| 记忆预算（Isabella 实测 9,705 token/日外推） | token | 入 512K？ |
|---|---|---|
| 单人 7 日 | 60,935 | ✔ |
| **单人 14 日** | **121,870** | ✔ |
| 单人 30 日 | 261,150 | ✔ |
| 25 人全量 1 日 | 218K | 累计可行 |
| 25 人全量 7 日 | 1.52M | ✘ 不可能全量 |

而 RAG top-30 每次只取 ~1,200 token。**全量 122K vs RAG 1.2K = 102 倍差距**，且 RAG 面对 14 天累积的 ~8,000+ 节点时完全可能漏掉第 3 天那个与后来矛盾的碎片。这是唯一能把"全量 vs RAG"变成**可判分对照实验**的情景。

## 4. 人设生成

### 4.1 格式（照 Smallville 七字段，精简掉不必要项） `[实测]`

```
name / age / innate(3形容词) / learned(20-35词含职业) /
currently(15-50词剧情钩子) / lifestyle(固定句式作息) /
daily_plan_req(20-30词日程锚) / living_area
```

**关键比例 `[实测]`**：抽象性格 : 具体行为 = **3.8% : 96.2%**（75 词 vs 1,880 词）。Smallville 只给 3 个形容词，其余全是行为描述。**不要写长篇性格小传。**

总词数控制：P0 三人版实测均值 78.2、中位 74、max 125；**正式 25 人设复核（2026-10-02）：均值 68 字、范围 30–135**；其中部分人设超出 125 上限，因剧情钩子（currently）长短不一所致，未影响运行质量。目标仍为 70–100 字、不超过 125。

### 4.2 AgentSociety 分布生成器（用于数值化属性）

`memory_config.py` 的 `DEFAULT_DISTRIBUTIONS` `[源码]`：
- age = UniformInt(18, 65)
- gender = Choice(Male, Female) 等权
- occupation = Choice(9 种) 等权
- work_skill = Pareto(α=8) 截断 [1, 950]
- emotion 6 维全初始化为 5

## 5. LLM 调用层（架构核心）

### 5.1 端点与实测参数 `[实测]`

- 端点：Atria-Dawn-Preview @ `discovery-api.intern-ai.org.cn`，OpenAI 兼容 POST
- `temperature=0`（3/3 次输出完全一致，确定性复现）
- `max_tokens ≥ 512`，**正式调用给 2048**：实测 completion=262 里 reasoning 吃 257，给小了 content 返回 null
- RPM 实测 **52.5**（2 分钟 105 请求，2 次 429）
- 单次延迟：max_tokens=8 → 0.29s；reasoning=478 → 2.5s；reasoning=853 → 5.6s

### 5.2 单次 JSON 合并调用（P0v2 实测通过）

**这是 P0 → P0v2 最大的架构改进。** 把 Smallville 的串行四级分解（sector→arena→object→emoji，每人每步 3–4 次调用）合并成**一次调用出全部字段**：

```json
{"sector": "...", "arena": "...", "object": "...", "emoji": "...", "action": "..."}
```

**P0v2 实测结果**：
- 格式合规 **0 失败**（72/72，fallback=0）：单次 JSON 比三层 few-shot 更好做严格校验
- 墙钟 525s → **66s**（8 倍加速）
- 新问题：4 线程并发打到 65.9 RPM 超过 52.5 限额，17/72 步吃 429

### 5.3 并发 + 令牌桶限速

- **并发必要性** `[实测]`：RPM 52.5 是 requests-per-minute 限额，但单次生成延迟 2.5–5.6s。串行 = 被生成时间拖死（P0 的 24.7 RPM 假象就是这么来的）
- **限速器**：裸线程池会超限（P0v2 实测 65.9），必须加令牌桶 ≤50 RPM + 指数退避重试
- 25 人是独立 agent，每步 25 人**并行**跑

### 5.4 地址解析与校验

Smallville 的唯一校验是 `if plan not in maze.address_tiles` → **直接抛错无降级**（源码字面 `#ERRORRRRRRR`）。我们的方案：
1. JSON 解析失败 → 正则兜底（从 ```` ```json{...}```` ` 或 `**Answer: X**` 抽取）
2. 抽取再失败 → fallback 到当前地点（降级而非崩溃）
3. `extract()` 函数实测 三级兜底 0 失败

## 6. 记忆层（主张核心）

### 6.1 事实基础 `[实测]`

Isabella 一游戏日（July1 快照 step-3-20）：
- 912 节点（event 762 / thought 146 / chat 4）
- 34,819 字符 = **8,705 token**（Smallville 自己的英文记账）
- **63%（573 条）是 "X is idle" 物件噪声**
- **75.1% 描述完全重复**（"refrigerator is idle" 重复 75 次）

### 6.2 中文 token 压缩比（本机实测，推翻早期估算） `[实测]`

```
测试: 269,997 字符 → 217,792 prompt_tokens
压缩比: 1.24 字符/token（中文几乎 1 字 1 token，不是 3 字/token!）
```

由此重算真实预算（按 6,304 条/7 日，每条约 25 字）：

| 记忆规模 | token | 512K 窗口 |
|---|---|---|
| 单人 7 日 | 6,304 条 ≈ 263K | ✔ 实测灌入成功（HTTP 200, 46s） |
| **单人 14 日** | ≈ **526K** | ⚠️ **轻微超限，必须压缩 idle 噪声** |
| 25 人 14 天 | 6.35M | ✘ 不可能全量 |

**P1v4 决定性实测**：直接灌 6,304 条记忆，`prompt_tokens=262,971`，HTTP 200，46 秒返回，全量窗口确实能装下并工作。

### 6.3 P1 三轮实验结论（本轮最重要的发现） `[实测]`

| 版本 | 规模 | 全量窗口 | RAG top-30 |
|---|---|---|---|
| P1 | 83 条 | ✔ 灰+东 | ✔ 灰+东 |
| P1v2 | 842 条 | ✔ | ✔ |
| P1v3 | 6,304 条 | (限速器故障 None) | ✔ 灰色 |
| P1v4 | 6,304 条 | ✔ **带推理链** | — |

**RAG 在"事实回忆"任务上三轮全部答对。** 原主张叙事"RAG 会断片"**站不住**。

但全量的回答质量有本质差异。P1v4 全量原话：

> "五天前第2天亲眼看到：灰色粗呢外套——这是原始视觉记忆；第3天复述'偏浅、好像灰色'仍接近原始；第4天周老师转述'黑色大衣'、第6天赵医生听说'蓝色工作服'都是**他人转述后失真**，不能作为依据。"

它分辨出了**时间线 + 来源可信度层级**（一手 vs 转述 vs 道听途说）。RAG 只给答案，没有判据。

### 6.4 主张叙事调整（v1.1 核心）

**旧叙事（作废）**："RAG 方案会断片"，P1 三轮证伪。

**新叙事（实测支撑）**：
> **全量时间线让 agent 能分辨传言在传播中的变异。**
> 情景 A 里传言经过 5 个放大器传播会发生变异（灰→黑→蓝）。只有记忆完整的人能指出"这是第 2 天我亲眼的原始记忆，其他都是转述失真"。RAG 检索到的只是"某个版本的答案"，无法分辨时间线与来源可信度。

这个角度与情景 A 的"信息追踪"主题完全咬合，且**是三轮对照实验测出来的真实差异**，不是营销想象。

### 6.5 判分标准与 P1v5 正式结果 `[实测]`

**标准：判据完整性**
- 0 分：只给答案，无判据
- 1 分：答案正确
- 2 分：答案正确 + 指出矛盾版本的存在
- 3 分：以上 + 分辨出哪个是一手记忆、哪些是转述失真

**P1v5 对照实验（6,304 条记忆，top-30 覆盖率 0.48%）：**

| | 全量窗口 | RAG top-30 |
|---|---|---|
| prompt_tokens | 138,454 | 830 |
| 延迟 | 23s | 2s |
| 回答 | "灰色的，一件灰色粗呢外套——**那天我亲眼在邮局门口看见的，后来别人传的黑的蓝的都不对**。" | "那人穿的是灰色粗呢外套。" |
| **判据完整性** | **3/3** ✅ | 1/3 |

**结论：主张正式成立。** 全量分辨出了一手 vs 转述失真（3/3），RAG 只给出事实答案（1/3）。这就是 v1.1 主张叙事的实验支撑。

### 6.6 P2 传播实验结果 `[实测]`

**P2v2（8 人 × 5 日，知情者主动转述，每天 2 轮配对）：**

```
扩散曲线: 第3天 3/8 → 第4天 5/8 → 第5天 8/8  (S 形)
种子转述: "我亲眼看见的，就在邮局柜台，那人穿件灰色粗呢外套，
          抱走一只缠了好几道胶带的旧纸箱，朝镇东头五金店方向去了。"
最终考核: 8/8 知情, 7/8 答对, 颜色分布 7灰/0黑/0蓝, 判据 0/8
```

**结论：传播机制成立，S 形扩散曲线涌现**（3→5→8，正是流行病学经典形状）。来源标签在传播中保留（P2 首轮周老师答出"这是老王亲眼所见的一手描述"）。

**当前局限**：变异未自然产生。短链条（5 天/8 人）里传播保真度很高（7 灰 0 黑 0 蓝）。P1v5 与正式方案中的传言变异（灰→黑→蓝）目前是**设计假设**，需 14 天/25 人正式跑验证。若正式跑仍不变异，情景 A 的"传言变异"叙事需改为"信息溯源"（仍由 P1v5 判据完整性支撑）。

钱老板案例（转述链衰减的实证）：知情但答 0 分：他听到的是赵医生"没留意"、孙裁缝"没瞧见"，细节在链路中丢失。

### 6.7 方案：时间窗口全量 + noise 控制

不做任何相关性打分，每个决策点按时间顺序灌最近 N token。但承认原始记忆 75% 是噪声，所以：

- **idle 物件状态不进记忆流**（直接砍 63% 噪声）：**因 14 日 ≈ 526K 轻微超限，此项从"优化"升级为"必需"**
- **5 分钟去重**（砍 75% 里的重复）
- 睡眠期零调用、行走中零调用、emoji/重要性打分离线规则化（0 次 LLM）

### 6.8 分层调用（Smallville 规模下才需要）

- 日常决策：小上下文（最近 ~50 条 + 人设）
- 深度回忆（A 的质问决策）：全量 512K
- 不每次都灌 512K（90s/次 × 25 agent ≈ 37 分钟/步，且有 lost-in-the-middle 风险）

### 8.3 AI 生成图素：不可行

- 本地：4 核 / 3.6G / 无 GPU，SD/Flux 推理显存不够

- 结论：免费像素包成熟度远超 AI 生成

## 9. 成本与时间

### 9.1 实测 RPM 真相 `[实测]`

| 测试 | 结果 |
|---|---|
| 2 分钟持续节流 | 105 请求 = **52.5 RPM**，103 成功 / 2 次 429 |
| 最小请求延迟（max_tokens=8） | 0.29 秒 |
| 真实任务延迟（reasoning 478/853） | 2.5 / 5.6 秒 |

**结论**：RPM≈50 是真实限额；P0 的 24.7 是串行实现的假象（被生成时间拖死，不是被请求限额拖死）。

### 9.2 25 人 14 天全程成本 `[推算，基于实测延迟]

| 方案 | 调用/步 | 1 游戏日（24 步） | 14 天 |
|---|---|---|---|
