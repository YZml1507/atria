## 0. 项目定位

- 交付物：离线渲染视频 + 说明.md + GitHub 仓库
- 核心卖点：每个居民拥有永不丢失的个人全量记忆（512K 窗口），别家用 RAG 会断片
- 约束：4核/3.6G/无GPU；RPM≈50（Atria-Dawn-Preview @ discovery-api.intern-ai.org.cn）；manim+ffmpeg+edge-tts
- 路线：不复现 Smallville，融合 Smallville（地图层级+作息锚点）+ AI Town（单句 plan）+ AgentSociety（分布生成器+显式关系图）

## 1. 情景 A：包裹错领（信息追踪弧线）

### 1.1 种子结构（对照 Smallville 25 人实证）

| 角色 | Smallville 原型 | 情景 A 定义 | 人数 |
|---|---|---|---|
| 意图持有者 | Isabella（currently 写派对，逢人就说） | 失主 Agent A：包裹被错领，要查清真相 | 1 |
| 态度种子 | Sam Moore（宣布参选） | 错领者：知道自己拿了别人的东西 | 1 |
| 碎片目击者 | —（Smallville 无此角色，我们的创新） | 各只看到碎片（方向/时间/部分特征，互相矛盾） | 3 |
| 好奇心放大器 | John/Yuriko/Giorgio/Adam/Latoya（5 人 currently 写 "curious about mayor"） | 高连接度人格，传言经他们扩散 | 5 |
| 中性背景板 | 18 人纯职业日常 | 纯职业日常 | 15 |

人设写法照 Smallville 实测格式：innate 固定 3 形容词 + learned 20–35 词含职业 + currently 剧情钩子 43–53 词 + daily_plan_req 20–30 词日程锚。**钩子只写「信息从哪来、到谁手里」，绝不写后果。**

### 1.2 弧线节奏（只控制种子投放时间，内容全部涌现）

- 第 1–2 天：潜伏期，日常建立关系基线
- 第 2 天夜：引爆点（包裹被错领，3 目击者各存碎片）
- 第 3–10 天：传播期（A 逢人打听；碎片经 5 放大器传播，每次复述经 LLM 记忆摘要 → 传言变异）
- 第 12–14 天：抉择期（A 决定当面对质谁）

**不写结局**：传言会不会先传到错领者本人？3 个碎片版本会不会互相冲突导致镇上分裂？A 会不会质错人？——全部是运行结果。

### 1.3 为什么情景 A 是 512K 卖点的最佳载体

A 最终的决策只取决于他个人 12 天里陆续听到的全部内容。单人 14 日 ≈ 122K token（稳入 512K），
而 RAG top-30 面对约 8,000+ 节点时完全可能漏掉第 3 天那个与后来矛盾的碎片。
这是唯一能把「全量 vs RAG」变成可判分对照实验的情景。

## 2. 测试矩阵（三级闸门）

### P-1：格式冒烟（先于 P0，约 10 次调用 / 1 分钟）

- **测什么**：Atria-Dawn-Preview 能否稳定输出 Smallville 提示词链要求的四级地址 JSON
- **为什么必须先做**：`execute.py` 唯一校验是 `if plan not in maze.address_tiles` → 直接抛错，**无降级**（源码字面 `#ERRORRRRRRR`）。模型输出格式崩了全链路就废
- **通过标准**：10/10 次调用输出合法 JSON 且地址在候选范围内

### P0：机制冒烟（3 人 / 1 游戏日 / 3 地点小图，~17 分钟）

- 24 步/日（粗粒度）× 3 人 × 2 调用 ≈ 150 次
- **通过标准**：144 步零崩溃 + 所有地址合法 + 完成一轮对话（含 `new_retrieve` 与 `curr_chat[-4:]` 截断）
- **失败后果**：修提示词链，不涉及卖点

### P1：记忆卖点生死闸门（5 人 / 7 游戏日，~34 分钟）

- 第 2 天给某 agent 埋一个细节碎片，第 7 天考他需要该碎片才能答对的决策题
- **对照组设计**：同一世界状态，agent A 灌全量时间窗口（122K 内），agent B 用 RAG top-30 检索
- **通过标准（不可妥协）**：全量答对 + RAG 答错 = 卖点成立
- **失败后果**：核心主张死，必须改卖点叙事（而非硬跑）

### P2：传播动力学（8 人 / 5 游戏日，~38 分钟）

- 种子参数（2 对立 + 5 放大器，见 1.1）能否让信息扩散出初始二人组
- **通过标准**：传到 ≥3 个初始不知情者
- **失败后果**：调种子参数/放大器人数（该参数目前是设计提案，零实测）

### 正式跑（P0–P2 全通过后）

25 人 14 天完整弧线，预估 7–12 小时（RPM≈50 下）。manim 离线渲染，产物视频 + 说明.md + 仓库。

## 3. 渲染方案

manim + **免费/可商用图素**（优先路线 B，已实测）：

### 3.1 授权现状（实测，来源：仓库 LICENSE / README 致谢 + itch.io 页面）

仓库代码是 Apache-2.0，但**图素与代码授权分离**。README 致谢三位作者：

- 背景美工 PixyMoon、室内美工 LimeZu、角色设计 ぴぽ(Pipoya/PIPOYA)

the_ville.tmx 实际引用 18 个 tileset，按授权分两组（实测逐文件归属 + 各图层 tile 数）：

| 组 | 占图比 | 授权 |
|---|---|---|
| 户外 `Cute RPG World 40 usd packet`（9 个 VXAce tileset） | 20,524 tile = **80.4%** | **付费 $40** |
| 室内 `v1/`（Room_Builder + interiors_pt1-5，LimeZu） | 5,019 tile = 19.6% | itch.io 有免费版 |
| 角色 精灵表 25 张（PIPOYA，96×128=12 帧） | — | **免费可商用可改，禁转售** |

### 3.2 三个路线（全部实测）

**路 A：直接用现成图素做视频**
- 户外付费包视频可引用，**仓库开源时不可推送**
- 优点：无需重做地图渲染管线，已有 `/home/ubuntu/town_overview.png`

**路 B（推荐）：全部换免费可商用包**
- 户外：Kenney roguelike pack（**CC0**，实测 0.7MB 单张 968×526=1920 块 16×16）或 PIPOYA FREE RPG World Tileset 32×32
- 室内：LimeZu `Modern_Interiors_Free_v2.2.zip`（1MB 免费版）
- 角色：PIPOYA FREE 32×32（1.3MB，64 角色，4 方向行走，商用 OK）
- 优点：**仓库可以整个推上 GitHub**，无授权地雷
- 代价：风格与 Smallville 原版不同，需要重新做 tileset→地图的映射；16×16 需放大到 32×32

**路 C：AI 生成图素——不可行**
- 本地：4 核 / 3.6G / 无 GPU，SD/Flux 推理显存就不够
- 云 API：可行但额外预算，且 32×32 像素小图 AI 质量不可控（像素风的核心是颜色数受限与清理轮廓，恰是扩散模型弱项）
- 结论：**不推荐**。免费像素包的成熟度远超 AI 生成的像素风

### 3.3 实测渲染能力

纯 PIL 从 the_ville.tmx + 18 tileset 渲染完整 140×100 小镇：17 图层全解析（Bottom Ground 14000 tile / Wall 1429 / 家具 1186 / 碰撞 2064 / 物品 680），合成俯视图 521 种唯一颜色，产物 `/home/ubuntu/town_overview.png`（4480×3200）。地图静态层渲染一次存 PNG，manim 只管动画层（移动精灵 + 对话气泡 + 右侧关系图实时演化）。
